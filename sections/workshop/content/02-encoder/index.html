Step 1: Load the data

We’ll use a curated sample of survey responses from RW3D. Participants of this study wrote about how the COVID-19 situation made them feel, and also self-reported a number of emotions regarding their current situation. They also reported which emotion best fit their current situation. To keep this workshop focused, we’ll only look at three of those emotions: anger, fear, and sadness.

First, let’s load the data and take a look at the dataset.

import pandas as pd

DATA_URL = "https://raw.githubusercontent.com/felixdidi/llm-content-analysis/main/sections/workshop/data/rw3d_workshop_sample.csv"
df = pd.read_csv(DATA_URL)

3
read_csv() downloads that CSV file and turns it into a DataFrame — pandas’ table format, here with one row per survey response. df is the conventional name for it.

Step 2: A category-specific encoder model

We’ll use SamLowe/roberta-base-go_emotions, a RoBERTa model fine-tuned on the GoEmotions dataset (58k Reddit comments, 27 emotions + neutral) — the most-used GoEmotions classifier on Hugging Face. This is a category-specific model: it was trained once, on one fixed set of labels, and can’t be repurposed for a different category set.

Loading and running the model on all 150 texts may take some time.

from transformers import pipeline

emotion_classifier = pipeline("text-classification",
                               model="SamLowe/roberta-base-go_emotions",
                               top_k=None,
                               truncation=True)

roberta_result = emotion_classifier(df['text'].tolist())

print(roberta_result)
1
pipeline is Hugging Face’s high-level shortcut: give it a task and a model name, get back something you can call directly on text.
2
"text-classification" is the task name for category-specific classifiers — models that return a score for each of their fixed labels.
3
The model we want, written as its Hugging Face ID (user/model-name). It gets downloaded automatically the first time you run this, which is why the cell takes a while.
4
top_k=None means “give me all 28 GoEmotions scores per text”, not just the single most likely label.
5
truncation=True cuts off texts that are too long for the model instead of erroring.
6
Runs the classifier over all texts at once. df['text'] is the text column, and .tolist() turns it into a plain Python list, which is what the pipeline expects as input.
7
Prints the raw result, so you can see how it is structured: one entry per text, each holding a label/score pair for all 28 categories.

Basically, that was it. We now have classifications for all texts in the dataset. We could save this directly — roberta_result is just a list of dictionaries (one per text, each holding label/score pairs for all 28 categories), and that’s exactly the structure of a JSON file. So instead of any Python-specific format, you could save it with Python’s built-in json module:

with open("roberta_result.json", "w") as f:
    json.dump(roberta_result, f)
1
Opens (creates) a file called roberta_result.json in write mode; the with block closes the file again automatically once it’s done.
2
Writes roberta_result into that open file, converted to JSON text.

and continue working in whatever language or tool you like from there — R, for example, can read the same file back in with the jsonlite package.

For this workshop, we’ll stay in Python and do some basic data wrangling below to turn these scores into a table we can work with.

Step 3: A task-specific (NLI) encoder model

Now we’ll use a model trained on Natural Language Inference (does a text entail a given hypothesis?) instead of on any fixed emotion label set. That single skill lets us classify text against any labels we like — including our three target emotions, directly, with no mapping step required.

This is slower than the category-specific model (it has to check every text against every candidate label).

nli_classifier = pipeline(
    "zero-shot-classification",
    model="MoritzLaurer/deberta-v3-base-zeroshot-v2.0",
)

template = "This text expresses {}."
candidate_labels = ['anger', 'fear', 'sadness']

nli_results = nli_classifier(df['text'].tolist(),
                             candidate_labels=candidate_labels,
                             hypothesis_template=template,
                             multi_label=True)

nli_results
1
Sets up a second pipeline — the same pipeline() function as in Step 2, just with a different task and model.
2
zero-shot-classification is the task name for NLI-based classifiers — “zero-shot” because the model was never trained on our specific 3 labels.
3
An NLI model fine-tuned for zero-shot classification: it judges how well a text supports a given hypothesis sentence.
4
The template that turns each candidate label into a full hypothesis sentence — the {} is the slot where each label gets inserted, giving e.g. "This text expresses fear."
5
The labels we want scores for. Unlike with the category-specific model, we’re free to choose these ourselves.
6
Runs the classifier over all texts, converted to a plain list with .tolist() just like before.
7
Hands over our three labels, so each text gets checked against each of them.
8
Hands over the sentence template from above, which is used to build one hypothesis per label.
9
multi_label=True scores each label independently (a text can score high on more than one emotion at once) instead of forcing the three scores to sum to 1.
10
Writing a variable name on its own at the end of a notebook cell displays its value — a shortcut for print() that formats the output a bit more nicely.

Same story here. That was it! nli_results is a list of dictionaries too — one per text, each with a sequence, labels, and scores entry — so it’s JSON-compatible in exactly the same way roberta_result was in Step 2:

with open("nli_results.json", "w") as f:
    json.dump(nli_results, f)
1
Opens (creates) a file called nli_results.json in write mode, same as before.
2
Writes nli_results into that file as JSON.

That file could be picked up in R or any other tool from here. We’ll keep working in Python below.

The order of labels/scores in each result is sorted by probability, highest first — it’s not the same as candidate_labels and differs from text to text. So instead of indexing by position, we pair each result’s labels with its scores and look up each emotion by name.

anger_scores = []
fear_scores = []
sadness_scores = []

for result in nli_results:
    scores_by_label = dict(zip(result["labels"], result["scores"]))
    anger_scores.append(scores_by_label["anger"])
    fear_scores.append(scores_by_label["fear"])
    sadness_scores.append(scores_by_label["sadness"])

nli_result_df = pd.DataFrame({
    "text": df["text"],
    "anger_score": anger_scores,
    "fear_score": fear_scores,
    "sadness_score": sadness_scores,
})

print(nli_result_df)
1
Three empty lists, one per emotion, which we fill up as we walk through the texts.
2
Loops over the model’s output — one result per text.
3
zip() pairs each label with the score in the same position, and dict() turns those pairs into a lookup table like {"fear": 0.87, "anger": 0.12, …}. This is what lets us fetch scores by name instead of relying on their order.
4
Looks up this text’s anger score by name and appends it to the anger list; the two lines below do exactly the same for fear and sadness.
5
Builds the results table, just like we did for the previous model.
6
The first column: the original texts.
7
One column per emotion, each filled with the list of scores we collected in the loop.
8
Prints the finished table.
